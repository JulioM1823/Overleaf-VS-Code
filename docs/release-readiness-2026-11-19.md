## Confirmed defects and corrections

| Severity | Defect and underlying cause | Correction and verification |
| --- | --- | --- |
| High, data integrity | Alternative-mode original-file replacement used an unconditional server upsert. A collaborator could edit after preflight and have that work overwritten; an extra preflight cannot make the operation atomic. | Removed the unsafe replacement action. Unknown/obsolete replacement choices fail closed before mutation. Recovery uploads create UUID-named copies and retain originals, base state, journal and pending drafts. Regressions cover stale choices, overlapping edits and disconnect during draft reads. A real hosted concurrent-edit scenario retained originals and the pending draft. |
| High, first use | A normal desktop VS Code profile supplies `globalStorageUri` through `vscode-userdata:`. The exclusive-writer store accepted only `file:`, so opening the first real authenticated project failed despite extension-test success. | Normalize only the trusted, local desktop alias to the same physical file path. Remote, web, authority-bearing, relative, query/fragment and unknown aliases remain rejected. Regression tests cover ownership exclusion, persistence and denied contexts. Actual hosted normal-profile editing and process restart subsequently passed. |
| Medium, portability | Recovery-copy suffixes could push valid Unicode original names beyond Linux's 255-byte filename limit. macOS APFS accepted a 290-byte name that Linux ext4 rejected with `ENAMETOOLONG`. | Bound generated names by both UTF-8 bytes and server character limits without splitting Unicode code points. Oversized extensions are bounded as part of the stem. Regression tests create real files and cover Chinese, emoji and long extensions; the original native Linux failure is retained. |
| Medium, responsiveness | PDF print PNG encoding ran through Chromium's main-thread idle scheduling. On the measured 1.80 run, callback wait dominated a 40.8-second 60-page preparation. | A packaged, print-only worker uses lossless PNG encoding with bounded startup/page waits, one page in flight, transferred/closed bitmaps and disposal on cancellation or failure. Unsupported/failed worker paths retain the prior encoder. No CSP, scripting or evaluation relaxation was introduced. |
| Medium, cancellation | The vendored print-page recursion ignored an inner promise. Cancellation between pages could reject without handling and strand the outer operation. | Replaced recursion with an awaited loop in the reproducible vendor patch. The actual-class regression now settles with the cancellation error and no unhandled rejection. |
| Medium, test evidence | A self-hosted restart wrapper could accidentally reuse a prior passing phase report after an early failure. | Each phase now has a fresh UUID and running/failed state; restart requires a newly added checkpoint. The parent preserves credential-free failure evidence, including nonzero child exits. Before/after reproductions and regression tests reject stale success. |
| Low, test isolation | Resuming arbitrary profiles or using macOS's longer canonical temporary path could respectively expose unrelated state or exceed Electron's Unix socket path limit. | Resumption requires a private task-owned direct child, ownership marker/token and exact canonical identity. The shorter OS-provided spelling is used only after verifying identical real paths. Focused profile and phase tests pass. |
| High, session integrity and account isolation | Any project-list/tag tree rejection triggered logout of the current named session. A delayed failure could delete credentials belonging to a newer login, including same-account credentials replaced by another window. Tree refresh could cancel a successful first login while its secret write was pending, or cancel an active newer login. Stale requests could publish old-account cache/UI data. | Numeric 401 or a same-origin exact login-endpoint redirect supplies only a safe authentication flag. Typed expiry is bound to the current session/key and tree intent; active login ownership prevents automatic expiry from cancelling sign-in while explicit logout still cancels it. Request/cache publication and cleanup have identity guards; the final synchronous node builder checks ownership after icon resolution. Legacy migration remains supported. Before-fix regressions and three independent race reproductions failed as expected; all corrected focused checks pass. |

## PDF performance and resource evidence

The actual 1.80.0 baseline 60-page print preparation took **40,799.8 ms**, with a mean main-thread `toBlob` callback wait of 678.4 ms per page. The exact [Chromium 108 implementation](https://chromium.googlesource.com/chromium/src/+/refs/tags/108.0.5359.215/third_party/blink/renderer/core/html/canvas/canvas_async_blob_creator.cc) contains a 1,000 ms idle-start fallback. The worker avoids that particular idle-task path; this is not a claim that every prior slow environment had an identical cause.

After correction, the macOS 1.80.0 preparations took **770.1/727.3 ms**, and 1.147.0 took **633.8/588.7 ms**. Each 20-cycle native fixture passed, with all measured generated page images matching the reference pixels, 27/27 tracked resources destroyed, zero active documents/blob URLs and zero unhandled rejections. PDF scripting and evaluation remained disabled. The 23 focused print/cleanup tests passed. Official vendor ZIP verification and patch reconstruction reproduced the generated vendor files byte for byte.

These are synthetic page-preparation measurements, not physical printing or controlled whole-system benchmarks. The fallback encoder can retain browser-dependent idle delays. Native process RSS, multi-hour resource growth and arbitrary large/hostile PDFs are not certified by these fixtures.

## Dependencies and limitations

No dependency was added for these fixes. The existing root dependency inventory still reports one moderate minimatch advisory; the runtime explicitly fixes `optimizationLevel` to 1, below the [advisory's documented trigger of 2 or higher](https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249). The fresh Linux root inventory reports zero high/critical advisories; chat dependencies report zero known advisories at the time checked. This is a scoped mitigation, not a clean root advisory inventory or proof that no vulnerabilities exist.

Vendored PDF.js 3.10.111 is retained for the supported editor floor. Native tests verify scripting/evaluation restrictions; disabling `isEvalSupported` is the [upstream workaround for CVE-2024-4367](https://github.com/mozilla/pdf.js/security/advisories/GHSA-wgrm-67xf-hhpq). Those restrictions do not establish complete parser security or make the old library a patched version. The legacy realtime fork and vendor assets require assessment beyond npm's registry inventory.

Unverified configurations include Windows client editions/ARM64, macOS Intel, WSL/Remote SSH/Codespaces, network filesystems, enterprise policies/proxies/keychains, all intervening VS Code versions, unusual third-party extension combinations, comprehensive historical upgrades, real power loss and physical printers. Forced termination can lose edits that have not yet been checkpointed. Synthetic injected failures are distinguished from real restricted-account, power-loss and network-appliance tests.
